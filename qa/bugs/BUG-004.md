# Reporte de Bug: BUG-004

**ID**: BUG-004  
**Título**: Ausencia de mecanismo de cancelación manual de apuestas en estado pendiente  
**Tipo**: Gap de UX / Regla de Negocio  
**Severidad**: Media  
**Prioridad**: Media  
**Módulo**: Apuestas de Cliente (`mis_apuestas.php`, `apostar.php`)  
**Ambiente**: PHP 8.3.1, MySQL 8.0, Windows  
**Estado**: Resuelto  
**Fecha de Resolución**: Septiembre 2026  

---

## 1. Descripción del Problema Original

Un usuario registrado que realizaba una apuesta en un partido programado (que aún no había comenzado) **no disponía de ninguna opción o botón en la plataforma para cancelar o anular la apuesta**.

---

## 2. Solución Aplicada (Fase 1)

1. Se implementó en `mis_apuestas.php` un botón **"Cancelar apuesta"** (`data-cy="btn-cancelar-apuesta"`) visible únicamente cuando `apuesta.estado = 'pendiente'` y `partido.estado = 'programado'`.
2. Se agregó la lógica de cancelación atómica con **orden unificado de bloqueos** (`usuarios` FOR UPDATE -> `apuestas` FOR UPDATE -> lectura informativa de `partidos` SIN FOR UPDATE) y verificación CSRF (`verificar_csrf()`).
3. Se devuelve el 100% del dinero apostado a `usuarios.saldo`, se crea la transacción `reembolso_cancelacion_cliente` y se pasa la apuesta a `estado = 'cancelada'`.

---

## 3. Evidencia Comparativa: Antes / Después

### 🔴 ANTES:
La tabla de `mis_apuestas.php` era estática sin columna de acciones ni botón para anular la apuesta.

### 🟢 DESPUÉS:
- Botón **"Cancelar"** visible en `mis_apuestas.php` con confirmación.
- Salida de transacción en base de datos:
```sql
SELECT id_usuario, tipo, monto, saldo_anterior, saldo_nuevo, referencia 
FROM transacciones 
WHERE tipo = 'reembolso_cancelacion_cliente' ORDER BY id DESC LIMIT 1;
```
