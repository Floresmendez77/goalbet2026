# Reporte de Hallazgo: GAP-002

**ID**: GAP-002  
**Título**: Funcionalidad de apuestas combinadas / parlays (`boletos`) sin implementar en el backend  
**Tipo**: Gap de diseño / Feature no implementada  
**Severidad**: Media  
**Prioridad**: Alta  
**Módulo**: Apuestas / Base de Datos (`apostar.php`, `mis_apuestas.php`, Tabla `boletos`)  
**Ambiente**: PHP 8.3.1, MySQL 8.0, Windows  
**Fecha**: Septiembre 2026  

---

## 1. Descripción del Hallazgo

La base de datos del proyecto incluye la estructura completa para soportar apuestas combinadas (parlays), consistente en la tabla `boletos`, la clave foránea `apuestas.id_boleto` y triggers de validación en MySQL. Asimismo, la vista de usuario `mis_apuestas.php` contiene código para renderizar el badge visual **"Combinada"** cuando `id_boleto` no es nulo.

Sin embargo, **no existe ningún código en toda la aplicación PHP** que admita la selección de múltiples partidos, el cálculo de cuota multiplicada acumulada ni la creación de registros en la tabla `boletos`.

---

## 2. Precondiciones

1. Base de datos `goalbet2026` importada desde `goalbet2026.sql`.
2. Usuario cliente autenticado en la plataforma.

---

## 3. Pasos de Auditoría de Código y Base de Datos

1. Inspeccionar el esquema de la base de datos MySQL:
   - Tabla `boletos` con campos `id`, `id_usuario`, `monto`, `cuota_total`, `ganancia_potencial`, `estado`, `referencia`.
   - Columna `id_boleto INT(11) NULL` en la tabla `apuestas`.
2. Inspeccionar `mis_apuestas.php` línea 71:
   ```php
   <td><?= e(ucfirst($a['tipo_apuesta'])) ?><?= $a['id_boleto'] ? ' <span class="badge bg-info text-dark">Combinada</span>' : '' ?></td>
   ```
3. Buscar referencias a `boletos` o `id_boleto` en todo el código PHP del proyecto.

---

## 4. Resultado Obtenido

Resultado de la búsqueda global de código (`Select-String` / `grep`):
```text
mis_apuestas.php:71: <td><?= e(ucfirst($a['tipo_apuesta'])) ?><?= $a['id_boleto'] ? ' <span class="badge bg-info text-dark">Combinada</span>' : '' ?></td>
```

- **0 coincidencias** en `apostar.php` para seleccionar 2 o más partidos.
- **0 scripts** de procesamiento de boletos.
- **0 controladores** o clases que gestionen la creación o liquidación de parlays.

---

## 5. Clasificación

Este hallazgo no constituye un error de ejecución en tiempo de corrida, sino un **Gap de diseño / Feature no implementada** (código scaffoldeado e incompleto a nivel de base de datos e interfaz).

---

## 6. Impacto en el Negocio

1. **Expectativa del usuario**: La presencia del badge "Combinada" sugiere la existencia del servicio de apuestas múltiples, pero el cliente no encuentra forma de armar un boleto en la UI.
2. **Desaprovechamiento de BD**: Estructuras relacionales complejas y triggers almacenados en MySQL quedan inactivos de forma permanente.

---

## 7. Recomendación de Implementación

1. Crear un widget de "Ticket / Boleto de Apuestas" en JavaScript/Bootstrap que permita acumular selecciones de distintos partidos.
2. Crear la lógica en `apostar.php` para procesar formularios con `id_boleto`, calculando `cuota_total = cuota_1 * cuota_2 * ... * cuota_n`.
3. Insertar el registro maestro en `boletos` y vincular los ítems individuales en `apuestas` compartiendo el `id_boleto`.

---
